# EVD-002: Secure evidence upload

## Goal

Allow citizens to upload evidence while enforcing strict validation and safe
storage so malicious or malformed files cannot compromise the platform.

## User

Citizen / reviewer / moderator

## Context

Evidence uploads are an important next step after the evidence model exists. The
system must validate content before accepting user uploads and must preserve a
secure storage path.

## Requirements

- Accept image and PDF uploads initially.
- Validate MIME type and content signature.
- Reject oversized or malicious input.
- Store files using generated keys rather than user-controlled names.
- Track content hash and size.
- Mark uploads as pending or visible only after validation passes.

## Acceptance criteria

### AC1: Valid evidence uploads are accepted
Given a supported image or PDF file under the size limit
When it is uploaded through the evidence API
Then it is accepted and saved with generated storage metadata.

### AC2: Invalid evidence uploads are rejected
Given a disallowed file type, malformed image, or suspicious PDF
When the upload is attempted
Then the request fails cleanly with a validation response.

### AC3: Secure storage is enforced
Given an accepted upload
When the file is stored
Then the path is generated by the backend and not derived from the user-provided filename.

## Data requirements

- evidence metadata
- original file name for display only
- MIME type
- file size
- checksum
- upload timestamp
- moderation state

## API requirements

- `POST /projects/{project_id}/evidence`
- `POST /comments/{comment_id}/evidence`
- `POST /reports/{report_id}/evidence`

## UI requirements

- upload form with validation states
- error handling for file size, format, and processing issues

## Security requirements

- no trust in client-provided MIME type
- reject executable file types
- reject suspicious archive content
- no application code execution or path traversal
- content stored outside executable application directories

## Provenance requirements

- upload timestamp and actor identity are preserved
- evidence is never automatically treated as an official source document

## Tests

- valid png accepted
- valid pdf accepted
- invalid exe rejected
- large file rejected
- checksum saved correctly
- file stored under generated storage key

## Dependencies

- EVD-001
- SEC-001

## Non-goals

- no public document indexing yet
- no OCR on this story
- no AI-based verification

## Definition of done

- secure evidence upload is implemented with validation and storage safety
- malicious or malformed input is rejected
- evidence metadata supports downstream verification workflows
